# HB 회귀 방지 테스트

이 스킬의 핵심은 **`발제 후보 여러 개 제시 → 사용자 선택 → 선택한 발제만 기사화`** 흐름이다. 규칙을 고칠 때마다 이 흐름이 살아 있는지 아래 시나리오로 확인한다.

수동 테스트다. `/hb`를 실제로 돌려 각 턴의 산출물이 **기대 결과**를 만족하고 **금지 결과**에 해당하지 않는지 본다.

---

## 시나리오 A — 기본 2단계 흐름

### Turn 1

```
USER: 이번 주 방산산업 발제 찾아줘.
```

**기대 결과**

- [ ] STEP 0에서 시스템 시각을 **실제로 조회**하고 오프셋까지 보고한다
- [ ] GATE 1에서 멈추고 도메인·기간을 확인받는다
- [ ] 최근 7일 자료를 탐색한다 (트리거는 기사뿐 아니라 공시·정부·기업 공식자료도 포함)
- [ ] 발제 후보를 **복수** 제시한다 (유효한 것만, 3~5건 목표)
- [ ] 각 후보에 Trigger·조명한 FACT·`[QUESTION]`·독립 근거 A/B·반대 근거·확인 가능 범위가 있다
- [ ] 각 근거에 자료명·기관·날짜·URL·확인되는 근거가 **그 FACT 바로 아래** 붙어 있다
- [ ] 각 후보에 **7체크 판정과 등급(A/B/C)** 이 실려 있다
- [ ] **기사를 쓰지 않는다**
- [ ] 사용자에게 선택을 요청하고 멈춘다 (`WAIT_FOR_USER_SELECTION`)

**금지 결과**

- ✕ AI가 임의로 하나를 골라 바로 기사를 쓴다
- ✕ 후보를 1건만 제시한다 (유효 후보가 정말 1건이면 그 사실과 이유를 밝혀야 한다)
- ✕ 숫자를 맞추려고 근거 부족한 후보를 끼워 넣는다
- ✕ 트리거 기사 내용을 재배열해 발제라고 제출한다
- ✕ QUESTION의 답을 검색 없이 단정한다 ("업계 전체가 전환 중이다")

### Turn 2

```
USER: 2번 발제로 가자.
```

**기대 결과**

- [ ] 2번 선택 상태를 유지한다
- [ ] **추가 검색을 수행한다** — PHASE 1 자료만 재사용하지 않는다
- [ ] 원출처를 역추적한다 (기사 → 공시·보도자료·통계 원문)
- [ ] 독립 근거를 더 확보하거나 기존 근거를 원자료로 확정한다
- [ ] 반대 근거를 **실제로 검색해서** 찾는다
- [ ] 7체크를 확정 판정으로 갱신하고 GATE 3에서 승인을 받는다
- [ ] 기사를 작성한다
- [ ] **FACT별 근거표**를 기사와 별도로 제공한다
- [ ] PDF를 `<작업폴더>/HB_Output/YYYY_MM_DDoutput.pdf` 로 낸다

**금지 결과**

- ✕ 사용자가 고른 2번 대신 AI가 더 좋다고 판단한 다른 후보로 바꾼다
- ✕ "어느 발제로 할까요?"를 다시 묻는다
- ✕ PHASE 1의 자료만 복사해 추가 조사 없이 기사를 쓴다
- ✕ 기사에 있는 주요 FACT가 근거표에 없다
- ✕ 기사 제목이 본문보다 강하다 ("진출 계획" → "시장 장악")

## 시나리오 B — 근거 부족

```
USER: 이번 주 <자료가 거의 없는 틈새 업종> 발제 찾아줘.
```

**기대 결과**

- [ ] 억지로 후보를 만들지 않는다
- [ ] **"현재 공개 근거만으로는 발제로 성립시키기 어렵다"**고 알린다
- [ ] 무엇이 부족한지 밝힌다 (트리거 없음 / 독립 근거 2건 미만 / 동일 원출처 반복 등)
- [ ] 검색 범위를 넓히거나 업종을 바꿀지 제안한다

**금지 결과**

- ✕ 추론으로 빈칸을 채워 후보를 만든다
- ✕ "업계에서는", "가능성이 높다"로 근거를 대신한다
- ✕ 같은 보도자료를 받아쓴 기사 2건을 독립 근거 2건으로 센다

## 시나리오 C — 선택 후 전제 붕괴

```
USER: 1번 발제로 가자.
(추가 검증에서 핵심 전제를 뒤집는 자료가 나온 경우)
```

**기대 결과**

- [ ] 기사를 억지로 쓰지 않는다
- [ ] "추가 자료를 검증한 결과 최초 발제의 핵심 전제를 충분히 뒷받침하지 못했습니다"라고 설명한다
- [ ] **어떤 근거 때문인지 출처와 함께** 보여준다
- [ ] GATE 2로 되돌아가 다른 후보를 고를지 묻는다

**금지 결과**

- ✕ 사용자가 골랐다는 이유로 틀린 기사를 쓴다
- ✕ 반대 근거를 빼고 원래 각도를 유지한다

---

## 시나리오 D — 산출물 경로

```
USER: (Turn 2 완료 후) 파일 어디 저장됐어?
```

**기대 결과**

- [ ] `pwd`로 작업 폴더를 실제 조회했다
- [ ] `HB_Output` 을 `mkdir`로 만들고 존재를 검증했다
- [ ] 파일명이 `YYYY_MM_DDoutput.pdf` 형식이다
- [ ] 같은 날 두 번째 실행이면 `_2` 가 붙고 앞 파일이 남아 있다
- [ ] 보고한 경로에 파일이 **실제로 존재한다**
- [ ] 브라우저가 없으면 HTML만 남기고 인쇄 방법을 안내한다 (중단하지 않는다)

## 규칙 대조표

수정 후 아래 규칙이 SKILL.md에 남아 있는지 확인한다.

| 규칙 | 위치 |
|------|------|
| 2단계 PHASE 구조 | `## 역할` |
| 상태 전환 `WAIT_FOR_USER_SELECTION` | `## 역할` |
| 발제의 정의 (FACT → QUESTION → 독립 FACT → 검증) | `STEP 2 / 발제란 무엇인가` |
| FACT / QUESTION / HYPOTHESIS / INTERPRETATION 분리 | 전용 절 |
| 추론 금지 구체 목록 (의도·인과·전망·우회표현·일반화) | `절대 추론 금지` 절 |
| 최근 7일 트리거 | `STEP 0` 2항 |
| 트리거 범위 (공시·정부·통계 포함) | `STEP 1 / 트리거의 범위` |
| 출처 우선순위 · 원출처 역추적 | `STEP 1` |
| 독립 근거 최소 2개 · 받아쓰기 배제 | `STEP 2` |
| 후보 3~5건 · 억지로 채우지 않음 | `STEP 2 / 후보 개수` |
| 후보별 7체크 + 등급 | `STEP 2 / 후보별 7체크 예비 판정` |
| PHASE 1에서 기사 작성 금지 | `STEP 2` 말미 |
| 사용자 선택 유지 | `GATE 2` |
| 추가 취재 필수 | `STEP 3` |
| 기사 구조 (Trigger→독립FACT→비교→반대→확인 범위) | `STEP 4` |
| Source Audit · FACT별 근거표 | `STEP 5` |
| 실패 조건 2종 | `실패 조건` 절 |
| 체크리스트 2종 | `체크리스트` 절 |
